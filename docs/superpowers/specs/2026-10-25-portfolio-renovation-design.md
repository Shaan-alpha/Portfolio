# Portfolio Renovation — "The model is a component"

**Date:** 2026-10-25
**Owner:** Shaan Satsangi
**Status:** Built and verified locally; not yet committed or deployed

## Brief

A full audit with every issue fixed, then a redesign that is more intuitive, has real 3D interaction, and does not read as AI-generated. It should look like the work of a design team and a full-stack team.

## Why the previous design read as generated

The June "terminal refresh" removed the obvious slop (purple gradients, glass, sparkles) but landed on another stock look:

- near-black (`#0b0d0e`) with one phosphor-green accent, plus a cream "paper" light mode (`#f4f2ec`, almost exactly the default generated cream);
- terminal costume on everything: a `~/section $` eyebrow over every heading, `[ bracket ]` buttons, `>` prompts, a build line joined with middle dots;
- one accented word in every heading ("not *demos.*", "Featured *work*", "Get in *touch*");
- template interactions: a typewriter subtitle, a dot-and-ring cursor, a scroll-progress bar, "SCROLL ↓", stat tiles, and the same fade-up on every section;
- the same bordered card everywhere, and the same tech list repeated three times (About chips, Skills tiers, Tools grid).

## Design

**Concept.** The site is built on Shaan's own line, "the model is a component, not the architecture". The hero is an exploded model of the shape his systems share. Interfaces, guards, orchestration, and memory and state are plates. The model is one yellow block with no plate of its own. Each production project below is drawn as the path work takes through it, in the same language. A system with two separate paths gets two diagrams: Atlas has a chat reply and a salience-gated morning briefing, and VouchRank has an AI-search audit and a review request.

**Colour.** Cool aluminium neutrals (`#eceef1` ground, `#111318` ink) with a graphite dark theme. One signal colour, `#ffc61a`, which only ever marks where a model runs. "Live" status uses a small green dot, a convention, not an accent.

**Type.** Archivo throughout. The expanded width (wdth 125) is the voice of the page at display sizes; reading text uses the normal width. Sentence case, no eyebrow labels, no accented words. Counts in running text are spelled out.

**Layout.** A 12-column grid with left-aligned text; section leads share one vertical axis (column 6). Work has a sticky project index with scroll-spy. Experience and education share one timeline.

**Depth language.** Things you can press are keys: a face plus a few pixels of dark side wall, sinking on hover and bottoming out on press. That covers the CTAs, Copy, the project links, and the layer buttons on phones, where the selected one stays pressed in like a latched switch. Pipeline steps are blocks, not keys. Their thin side is drawn in the light line colour and they never move, because there is nothing to press. Beside the model on wide screens, the layer buttons are outlined tags at the end of each leader line.

**3D interaction.**
- Drag to orbit, with inertia. Vertical drag tilts within limits. Touch uses `pan-y`, so page scrolling is never trapped.
- Hovering (with a real mouse) or clicking a plate or its tag lifts that layer and dims the rest. The caption explains the layer and links to the projects that back each claim. Keyboard focus previews a layer, and Tab carries on into its links. Escape clears the selection.
- A one-line hint sits above the tags on wide screens ("Drag to turn the model. Select a layer for details."). It only offers turning when there is a model to turn.
- The stack opens and turns a little as the hero scrolls away (not under reduced motion).
- On load the parts grow out of their plates from the bottom up, and the model block makes a quarter turn. That is the one orchestrated moment on the page.
- Render on demand: the loop stops when nothing moves and pauses offscreen. Resizing redraws in the same frame and re-reads the pixel ratio.
- If the WebGL context is lost, the scene is disposed and the drawing takes over.

**Progressive enhancement.** `geometry.ts` holds the orthographic camera maths for both the WebGL scene and an SVG drawing. The server renders the drawing, with the tags already at their exact resting positions. That holds because the stage never drops below the drawing's aspect ratio on wide screens. The 3D model then replaces the drawing with a crossfade. Without WebGL or with Save-Data, the drawing and the working layer buttons are the experience. With JS off, the drawing and the default caption remain, but the buttons do nothing.

## Verification

- `npm run lint`, `npm run typecheck` (app and Worker), `npm test` (19/19) and `npm run build`: all clean.
- 44 scripted browser checks (Playwright on local Chrome), including:
  - interactions: hover, select and Escape; drag and reset; 3D picking; the theme toggle; scroll-spy;
  - the contact form: success and rate-limit paths, and the honeypot rename;
  - keyboard and touch: the skip link; mobile menu focus and `inert`; tabbing into "Seen in" links; touch double-tap;
  - fallbacks: no WebGL, WebGL context loss, JS off, reduced motion, a 20px default font size;
  - layout: pipeline labels inside their blocks from 820 to 1920px; resting tag positions matching the live model (0.0px off at 1024×900, 1280×1000, 1440×900 and 1920×1080);
  - accessibility: axe in both themes.
- Static export served with the production `_headers`: the 3D model loads under the live CSP with no violations, `og.png` is served as `image/png`, and 404 returns 404.
- Two independent review rounds:
  - First, one reviewer found 8 issues, all fixed.
  - Second, three reviewers worked through different lenses, with one skeptic per finding, and found 20 more, all fixed. They included an Atlas note that added two failover chains into "seven providers", the miscount commit `5cf16f6` had corrected.
